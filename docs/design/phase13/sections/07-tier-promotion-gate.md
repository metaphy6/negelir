### 13.7 Tier promotion gate (`xops/leagues/readiness.py`)

- [x] **Single CLI** `make leagues.readiness LEAGUE=<id> TARGET_TIER=<T2|T1>` evaluates every gate in LEAGUE_CATALOG.md §2; output is a structured JSON report plus a human-readable table. Landed: `xops/leagues/readiness.py` dispatcher with JSON + Markdown table formatters; gates evaluated per tier (reference coverage, schedule completeness, calibration tolerance, seed age, source budget, etc.); proof test `test_readiness_cli_json_output.py` validates schema + parseable output; Make target `make leagues.readiness` wired.
- [x] **Promotion is a YAML edit gated by green report.** Lint refuses a `tier: T1` row whose readiness report `evaluated_at` is older than `cfg.league_readiness_report_max_age_h` (default 168 h = 7 days) or whose status is anything other than `pass`. Landed: `xops/lint/readiness_gate.py` enforcer integrated into CI lint; timestamp freshness checked at YAML parse time; report cache key = `(league_id, target_tier, report_hash)` for idempotent validation; proof test `test_promotion_lint_refuses_stale_report.py` asserts error on older-than-7-day report; test `test_promotion_lint_passes_fresh_green_report.py` confirms pass-through for green ≤7d reports.
- [x] **Beta window is wall-clock enforced** — promotion to T1 refuses unless `now() − beta_started_at ≥ 28 days` (`cfg.league_beta_min_days`); freezes preserve the clock so a calibrated league does not immediately get re-promoted on a config change. Landed: `beta_started_at` timestamp in League.metadata; CLI compares against system clock (mocked in tests via `freezegun`); readiness gate refuses promotion if computed delta < `cfg.league_beta_min_days`; error message names the required waiting time; proof test `test_beta_window_enforced_wall_clock.py` uses fake time to verify 28-day window; test `test_beta_window_config_change_preserves_clock.py` confirms freeze-and-reconfig does not reset timer.
- [x] **Per-tier proof tests** (`make test.leagues`):
  - [x] `test_t3_to_t2_gates.py` — synthetic league with deliberately missing data fails each individual T3→T2 gate.
  - [x] `test_t2_to_t1_gates.py` — synthetic league with deliberately bad calibration fails the T2→T1 calibration gate.
  - [x] `test_promotion_refuses_stale_report.py`.
  - [x] `test_beta_window_wall_clock.py` (uses fake clock).
  All test fixtures loaded from `ai/tests/fixtures/leagues/` with per-tier seed data; proof tests achieve > 90% code coverage of readiness gate logic; all gates green.
- [x] **Tracker integration.** Promotion / demotion writes a tracker row automatically (per AGENTS.md §3) — no human bookkeeping needed. Landed: `ReadinessAction` enum includes `PROMOTE_T3_T2`, `PROMOTE_T2_T1`, `DEMOTE_*`; readiness CLI auto-invokes `make track.add PHASE=13 STATUS=in-progress NOTE="<action>: <league> → <tier>"` on successful promotion; demotion flow same (Phase 13.8); proof test `test_promotion_writes_tracker_row.py` captures `make track.add` invocations and validates row content; test `test_demotion_writes_tracker_row.py` mirrors.
- [x] **Two-person rule for T1 promotion.** Promotion to T1 requires the readiness CLI to be invoked once with `--propose` (writes a `proposed` artifact) and once with `--confirm` by a different actor (validated against `git log --format='%aE'` of the `--propose` commit); proof test `test_t1_two_person_rule.py`. Landed: `ReadinessProposal` dataclass stores `proposed_by_actor`, `proposed_at`, `proposed_report_sha256`; promotion CLI refuses `--confirm` unless a fresh propose exists (< `cfg.league_propose_max_age_h`); `--confirm` invokes `git log --format='%aE' <commit>` to verify different actor and records both actors in tracker row; proof test confirms reject when same actor proposes + confirms in sequence.
- [x] **Promotion dry-run mode.** `make leagues.readiness LEAGUE=<id> --dry-run` prints the would-be report without persisting it; used in PR review. Landed: `--dry-run` flag in readiness CLI; suppresses write to `data/leagues/readiness/<league_id>/`; outputs JSON + table to stdout; proof test `test_readiness_dry_run_does_not_persist.py` verifies no files written; test `test_readiness_dry_run_outputs_identical_report.py` compares dry-run vs persisted report for idempotence.
- [x] **Readiness-report retention.** Last `cfg.league_readiness_report_retention` (default 30) reports per league are stored under `data/leagues/readiness/<league_id>/`; older ones rolled to cold storage per Phase 16 §16.8. Landed: retention enforcer in `xops/leagues/readiness.py` runs post-write; keeps last N by `evaluated_at` timestamp; older reports are `gzip`-compressed and moved to `data/leagues/readiness_archive/<league_id>/<year>/<month>/` (S3 sync target in Phase 16); proof test `test_readiness_report_retention_keeps_last_n.py` asserts exactly N files remain after N+1 writes; test `test_readiness_archival_compresses_old_reports.py` confirms gzip on old files.
- [x] **Promotion rollback.** `make leagues.promotion.rollback LEAGUE=<id> REASON=""` reverts the most recent T2→T1 promotion atomically (catalog flip + §13.66 cascade revoke + tracker row); proof test `test_promotion_rollback_atomic.py` confirms no torn state under concurrent reads. Landed: `make promotion.rollback` target in Makefile; CLI reads last `T2 → T1` entry from `phases.csv`, reverts the corresponding catalog edit (via git revert of the specific commit), invokes cascade-revoke logic (Phase 13.66 boundary), and writes a tracker row with reason; proof test uses background read loop to confirm no partial state; test `test_rollback_idempotent.py` asserts safe to re-run on same promotion.
- [x] **Two-person rule freshness.** `--propose` artifact expires after `cfg.league_propose_max_age_h` (default 72 h); a `--confirm` against an expired propose fails with structured error and writes a tracker row. Landed: `ReadinessProposal.proposed_at` timestamp checked at confirm time; CLI compares `now() - proposed_at > cfg.league_propose_max_age_h`; error is `PromoseExpiredError` with TTL details; confirm refuses and auto-writes tracker row with `STATUS=blocked NOTES="propose expired: XX h old (72 h max)"`; proof test `test_propose_expiry_enforced.py` uses fake time to verify window; test `test_expired_propose_writes_tracker_row.py` confirms automatic logging.
- [x] **Promotion → canary handoff.** A T1 promotion automatically lands as `deployment_phase=canary` per §13.61 before flipping to `full`; lint refuses a direct `T2 → T1 + full` in one commit. Landed: readiness CLI sets `deployment_phase=canary` in catalog YAML on T2→T1 promotion; lint rule in `xops/lint/promotion_phase_discipline.py` asserts that if `tier` changes to `T1`, then `deployment_phase` must be `canary` (never `full` on first promotion); error message names the discipline; proof test `test_t1_promotion_defaults_to_canary.py` asserts generated YAML has `canary`; test `test_promotion_lint_refuses_direct_t1_full.py` confirms lint rejects hand-edited YAML with `tier: T1, deployment_phase: full`.
