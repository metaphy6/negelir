### 13.15 Reactor isolation & per-league startup quarantine

- [x] **One bad league cannot poison others.** A preset that fails to import, a calibration profile with a bad YAML, or a missing mock seed quarantines that league only — the rest stay live (proof test `test_one_bad_league_isolated_at_startup.py`). Landed: startup loader wraps per-league import in try/except; on failure, sets `quarantine_reason` in league metadata + skips further processing; other leagues proceed normally; proof test creates malformed preset, verifies only that league quarantined, others load.
- [x] **Per-league reactor scope.** `LivePredictorReactor` and `TrainerReactor` (Phase 5) carry the `league_id` on every inflight context; a panic in one league's reactor bubbles to that league's DLQ only. Landed: reactor context dataclass includes `league_id`; panic handler routes error to `predict.dlq{league_id=<id>}` topic; other leagues' in-flight tasks unaffected; proof test injects panic into one league's reactor, verifies other league tasks continue + unaffected league metrics steady.
- [x] **Quarantined leagues surface on the ops console** with a `quarantine_reason` and a `make leagues.unquarantine LEAGUE=<id>` command (writes a tracker row). Landed: ops console Phase 8 (reference; not Phase 13); /v1/leagues endpoint returns `quarantine_reason` field; frontend renders quarantine banner; `make leagues.unquarantine` CLI clears `quarantine_reason` + retries startup; writes tracker row with reason; proof test verifies banner appears on ops console for quarantined league.
- [x] **DLQ partitioning.** `<topic>.dlq` is keyed on `league_id`; a flooded league does not crowd out others' DLQ entries (cap per league = `cfg.swarm_dlq_max_len_per_league`, default 1 000). Landed: DLQ subscriber tracks per-league queue depth in Redis; on arrival, checks depth vs cap; if >= cap, drops oldest entry for that league (FIFO per league); proof test floods one league's DLQ, verifies cap enforced, other leagues' DLQ unaffected.
- [x] **Per-league circuit breaker.** A league that produces > `cfg.league_error_rate_circuit_open` (default 50 % over 5 min) errors trips a circuit breaker; predictions for that league return `503 + X-Reason: league_circuit_open` until the rate recovers below `cfg.league_error_rate_circuit_half_open` (default 5 %); proof test `test_league_circuit_breaker_state_machine.py`. Landed: per-league error counter in Redis with 5 min window; predictor pre-gate checks error rate; if rate > threshold, returns 503; watchdog monitors recovery; proof test triggers 50% error rate, verifies 503 responses, waits for recovery, verifies circuit half-open, then re-enable.
- [x] **Quarantine surfaces in catalog GET.** `/v1/catalog` returns `quarantined: true` + `quarantine_reason` for affected rows so frontends can render the right UI state. Landed: catalog API endpoint includes optional `quarantine_reason` field in League schema; populated from metadata if set; frontend renders quarantine notice; proof test creates quarantined league, queries catalog, verifies `quarantined: true` field.
- [x] **Forced-quarantine drill in CI.** `make chaos.league.quarantine LEAGUE=<id>` flips a league into quarantine in a stamped test; asserts other leagues' SLO metrics are unaffected for the duration. Landed: `xops/chaos/league_quarantine.py` chaos driver; `make chaos.league.quarantine` target in Makefile; quarantines a league, runs prediction load for all leagues, verifies other leagues' metrics (latency, success rate, dlq depth) unchanged over 5 min; proof test confirmed.
