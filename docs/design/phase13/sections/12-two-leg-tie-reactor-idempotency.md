### 13.12 Two-leg tie reactor & idempotency

- [x] `swarm/proofreader/tie_reactor.py` — keyed on `tie_id = sorted([stable_id1, stable_id2])`; consumes both legs' `predict.final` candidates and emits one `predict.final.tie`. Landed: tie_reactor module in proofreader swarm (Phase 5 sub-component); subscribe to `predict.final` topic; accumulate legs by `tie_id` key in Redis; emit tie prediction on receipt of second leg; proof test `test_tie_reactor_emits_on_second_leg.py` sends leg1, verifies no emit, sends leg2, verifies emit.
- [x] **Idempotent across leg arrival order** — replay legs in any order ⇒ identical tie prediction (proof test `test_tie_reactor_idempotent_under_replay.py`). Landed: tie_reactor deterministically orders legs in `tie_id` computation (`sorted()`); prediction logic is commutative in leg inputs (XOR-style vote aggregation); proof test replays leg1 then leg2, then leg2 then leg1 in same session, verifies identical tie output.
- [x] **Idempotent across leg revision** — a corrected leg score re-emits the tie prediction with a monotonically-increasing `revision`; proof test `test_tie_reactor_revision_monotonic.py`. Landed: `TiePrediction.revision` field auto-increments on each re-compute; tie_reactor compares current revision vs prior in Redis; if new revision > old, emits update with new revision number; proof test sends leg1 (v=1), then revised leg1 (v=2), verifies tie emitted twice with revisions 1, 2 in order.
- [x] **Coverage** — every `two_leg_knockout` competition in the catalog has at least one tie in the backtest corpus. Landed: `ai/tests/test_two_leg_competition_coverage.py` iterates catalog competitions with format=`two_leg_knockout`, asserts each has >= 1 fixture pairing in `data/backtest/`; CI fails on gap; gap forces catalog audit or backfill.
- [x] **Cross-source leg reconciliation.** Two sources reporting the same leg's score must collapse to one tie input; reactor refuses to compute tie until `cfg.tie_source_quorum` (default 1 of N — first-write-wins with reconcile on conflict). Landed: tie_reactor stores `legs[source_id]` map per leg; quorum logic: if `len(distinct_scores) > 1`, stores in reconcile queue + emits `predict.tie.reconcile` event; otherwise accepts quorum-reached state; proof test `test_tie_reconciliation_on_conflicting_sources.py` sends conflicting scores, verifies reconcile event + no tie emit.
- [x] **Tie DLQ.** A tie that fails reconciliation lands in `predict.tie.dlq` with both legs' source provenance attached; surfaces on Phase 8 ops console; `make ties.replay TIE_ID=<id>` retries. Landed: failed-reconcile ties stored in `predict.tie.dlq` topic; DLQ entry includes `legs[]`, `conflicting_scores[]`, `first_attempt_at`; ops console Phase 8 subscribes + renders DLQ panel; `make ties.replay` CLI resends tie to input topic, watchdog re-attempts; proof test `test_failed_tie_lands_in_dlq.py` triggers reconciliation failure, verifies DLQ entry.
- [x] **Three-leg edge case.** If a competition declares a `replay_leg` (e.g. neutral-venue replay after two-leg draw, historical FA Cup format), reactor accepts a third leg without breaking idempotency — the `tie_id` keys on the canonical pairing, `legs[]` accumulates monotonically (proof test `test_tie_reactor_three_legs.py`). Landed: `TiePrediction.legs` is a list, not a dict; tie_id computed from canonical pair (first two); third leg appended without changing tie_id; output aggregates across all legs; proof test sends legs 1, 2, 3 in order, verifies one tie with `len(legs) == 3`.
- [x] **Aggregate winner determinism.** Tied aggregate → away-goals (era-aware §13.13) → extra-time → penalties; each step deterministic and audited (proof test `test_tie_winner_resolution_deterministic.py`). Landed: `TiePrediction.winner_by` field captures applied rule (one of `aggregate`, `away_goals`, `extra_time`, `penalties`); era gates applied per competition (COMPETITIONS.md §4 + era field in Competition record); determinism enforced by fixed RNG seed in penalty shootout logic; proof test feeds two identical ties, verifies same `winner_by` + same penalty sequence.
- [x] **Leg cancellation propagation.** A leg flipped to `abandoned` (§13.17) drops the tie's `predict.final.tie` and emits a `predict.invalidated` event; downstream Phase 16 emitter shards re-emit with the void payload. Landed: Phase 13.17 incident reactor sets leg.status = `abandoned`; watchdog monitors status change + finds dependent ties; for each tie, emits `predict.invalidated{tie_id, reason: "leg_abandoned", timestamp}`; Phase 16 emitter (downstream) consumes invalidation + re-emits all feed records for that tie with null payload; proof test `test_abandoned_leg_invalidates_tie.py` flips leg status, verifies invalidation event.
