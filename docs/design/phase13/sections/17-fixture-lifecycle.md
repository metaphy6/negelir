### 13.17 Fixture lifecycle (postpone / abandon / replay / awarded)

> Fixtures are not immutable. A fixture may be postponed, rescheduled,
> abandoned mid-match, replayed entirely, awarded by federation
> committee (forfeit / 3-0 walkover), or annulled. Each transition
> invalidates downstream predictions and forces a revision bump.
> Retires assumption §13.0 #18.

- [x] **`Fixture.status` FSM.** `scheduled → live → completed` is the happy path; off-path transitions: `scheduled → postponed → rescheduled (new_fixture_id, original_fixture_id link) | cancelled`, `live → suspended → resumed | abandoned`, `completed → annulled | awarded(score, reason)`. FSM lives in `common/schemas/fixture_lifecycle.py`; transitions are deterministic and append-only-audited. Landed: `FixtureStatus` enum with all states; FSM transition logic in `Fixture.transition()` method; invalid transitions raise `FixtureTransitionError`; audit log stored in `fixture.status_history`; proof test `test_fixture_status_fsm.py` asserts all valid transitions allowed, invalid ones rejected.
- [x] **Prediction invalidation event.** Any non-terminal exit (`postponed`, `abandoned`, `annulled`, `awarded`) emits `predict.invalidated.v1{fixture_id, prior_revision, new_state, reason}`; Phase 16 emitter re-shards. Landed: watchdog subscribes to fixture lifecycle changes; on exit state, emits invalidation event to bus; Phase 16 emitter (downstream) consumes + re-shards affected feed records; proof test `test_fixture_lifecycle_invalidates_predictions.py` creates prediction, transitions fixture, verifies invalidation event emitted.
- [x] **Per-state proof tests.** `test_fixture_lifecycle_<state>.py` for each transition: postpone-then-reschedule keeps `original_fixture_id` linkage; abandoned-with-resumption splits into `original_id (abandoned, score=at-suspension)` + `new_id (resumed, format=continuation)`; awarded-walkover overrides the on-pitch score with provenance `awarded_by=federation, reason=...`. Landed: proof tests implemented; each covers the state transition and its side effects; all green; proof test `test_fixture_postpone_reschedule_linkage.py` verifies chain.
- [x] **Revision monotonicity.** Each lifecycle transition bumps `Fixture.revision`; downstream consumers gate on `revision >= last_seen` (proof test `test_fixture_revision_monotonic.py`). Landed: `revision: int` field in Fixture; auto-increment on any transition; consumer logic checks `new_revision >= last_observed_revision` before accepting update; proof test verifies revision always increases, never decreases.
- [x] **Two-leg tie cancellation.** §13.12 reactor must consume invalidation events and re-emit ties accordingly (covered by §13.12's leg-cancellation propagation test). Landed: tie_reactor implementation (Phase 13.12 bullet 9); test `test_leg_cancellation_invalidates_tie.py` verifies tie invalidation on leg status change.
- [x] **Walkover calibration.** Awarded walkovers (3-0 default by FIFA convention) feed neither the calibration corpus nor the betting-market predictor; sentiment + news consume them with a `synthetic=true` flag (proof test `test_walkover_excluded_from_calibration.py`). Landed: fixture loader marks awarded fixtures with `synthetic=true`; backtest loader excludes them from training set; proof test creates awarded fixture, verifies it's excluded from calibration corpus but included in news.
- [x] **Operator override CLI.** `make fixture.transition FIXTURE_ID=<id> TO=<state> REASON=""` is the only non-source-driven path; writes a tracker row + `identity.merge.v1`-style audit topic. Landed: `xops/makefile/fixture.py` dispatcher; `make fixture.transition` target validates transition, executes, emits audit event, writes tracker row; proof test invokes override, verifies audit + tracker entry.
- [x] **Source-disagreement on lifecycle state.** Two sources reporting conflicting states (one says `live`, another says `postponed`) hold the fixture in `disputed` until quorum (`cfg.fixture_lifecycle_quorum`, default 2 of N) is reached; ops console surfaces the dispute. Landed: `disputed` state in FSM; fixture coordinator stores per-source state reports; when quorum not reached, fixture stays in `disputed`; ops console displays conflict; proof test sends conflicting updates from two sources, verifies `disputed` state until quorum.
