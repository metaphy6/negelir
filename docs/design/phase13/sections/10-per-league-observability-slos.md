### 13.10 Per-league observability & SLOs

- [x] **Five canonical metrics** per league, exposed by Phase 11 telemetry:
  - `negelir_league_ingest_lag_seconds{league_id, plane}`
  - `negelir_league_prediction_emit_total{league_id, format, status}`
  - `negelir_league_calibration_deviation{league_id, window=7d|14d|30d}`
  - `negelir_league_dlq_depth{league_id, topic}`
  - `negelir_league_scraper_success_ratio{league_id, source}`
  Landed: metrics defined in `ai/common/telemetry.py` + `server/internal/telemetry/` with per-league labels; exported via Prometheus HTTP endpoint; Phase 11 orchestrator (reference; not in Phase 13 scope) ingests metrics; proof test `test_league_telemetry_metrics_exported.py` scrapes endpoint, parses schema, asserts all five metrics present with proper labels.
- [x] **Per-league SLO contract** documented in `docs/design/LEAGUE_CATALOG.md` §11 (added in this phase): T1 = 99.5 % scraper success, ≤ 60 s ingest lag p95; T2 = 98 % / 180 s. Landed: SLO table added to LEAGUE_CATALOG.md with tier, metric, target, and rationale; metrics enforcement deferred to Phase 14 tier-enforcement (this phase documents contract only); proof test `test_league_slo_contract_documented.py` verifies LEAGUE_CATALOG.md contains SLO table.
- [x] **Burn-rate alerts** wired against the catalog row's tier — alerts route to the ops console (Phase 8) with `league_id` as a primary label. Landed: Phase 8 ops console work (reference; not Phase 13 scope); Prometheus alert rules defined in `infra/prometheus/rules/league_slos.yaml` with conditions per tier (1h fast-burn, 6h slow-burn per SLO); alerts tagged with `league_id` for routing; ops console subscribes to `ops.alert.v1` bus topic; proof test `test_burn_rate_alert_route_to_ops.py` mocks alert, verifies ops console receives message.
- [x] **Predictor vote dominance metric.** `negelir_league_vote_dominance{league_id}` ≤ 0.6 (no single predictor dominates) — verified at promotion (LEAGUE_CATALOG.md §2.1) and continuously. Landed: predictor swarm emits vote distribution per league (via `vote_shares` list in Phase 5 swarm contract); `negelir_league_vote_dominance = max(vote_shares)` exported as gauge metric; readiness gate enforces metric <= 0.6 before T1 promotion; continuous monitor (Phase 8) alerts if metric exceeds 0.65 at any time; proof test `test_vote_dominance_metric_computed.py` verifies metric value = max of vote shares.
- [x] **Cardinality budget.** Total label cardinality across the five metrics ≤ `cfg.league_metrics_cardinality_budget` (default 50 leagues × 9 planes × 5 sources ≈ 2 250); exceeding the budget is a CI fail. Landed: `ai/tests/test_league_telemetry_cardinality.py` scrapes Prometheus (mocked), counts unique label combinations, asserts total <= cap; nightly CI run fails if cardinality exceeds budget, preventing metric explosion.
- [x] **Per-league error budget + burn-rate policy.** Each tier carries a 30-day error budget (T1 = 0.5 % unavailability, T2 = 2 %); fast-burn (>2x in 1 h) pages immediately, slow-burn (>1x sustained 6 h) opens a tracker row. Documented in `LEAGUE_CATALOG.md` §11. Landed: error budget thresholds documented in LEAGUE_CATALOG.md §11; Prometheus alert rules per tier with burn-rate conditions; ops console auto-pages on fast-burn, auto-writes tracker on slow-burn; proof test `test_error_budget_burn_rate_policy.py` verifies documented thresholds match alert rule conditions.
- [x] **Vote-dominance with confidence interval.** The dominance metric reports its 95 % CI; promotion gates against the upper bound, not the point estimate. Landed: predictor swarm computes vote-dominance CI using bootstrap resampling of vote history (default window 10 d); CI exported as separate metric `negelir_league_vote_dominance_ci_upper{league_id}`; readiness gate checks upper CI <= 0.65 before T1 promotion; proof test `test_vote_dominance_ci_computed.py` verifies CI is wider than point estimate; test `test_promotion_gate_checks_upper_ci.py` confirms gate uses upper CI, not point.

#### 13.10.5 T2 dwell-time ceiling

- [x] **Hard wall-clock ceiling.** A league sitting at T2 longer than `cfg.league_t2_max_dwell_days` (default 180) auto-demotes to T3 with a tracker row + ops alert (`league_t2_dwell_exceeded`); proof test `test_t2_dwell_ceiling.py`. Prevents permanent-beta drift. (Retires assumption §13.0 #35.) Landed: `promoted_to_t2_at` timestamp in League.metadata; watchdog checks `now() - promoted_to_t2_at > cfg.league_t2_max_dwell_days` hourly; auto-demotion triggers same flow as SLO breach (Phase 13.8); proof test uses fake clock to verify 180-day boundary.
- [x] **Dwell-clock pause.** The dwell clock pauses while a league is `quarantined` (§13.15) or its source coverage drops below T2 minimums; resume timestamp is audited. Landed: watchdog honors `quarantined_at / quarantined_until` fields in League.metadata; dwell-clock calculation skips quarantine intervals; resume event writes audit log to `data/leagues/audit/<league_id>.log` with timestamp + reason + duration paused; proof test `test_dwell_clock_paused_during_quarantine.py` sets quarantine window, verifies dwell delta excludes it.
