# 🔐 Security Design

> Companion to Phase 7 and Phase 9 of [`../planning/ROADMAP.md`](../planning/ROADMAP.md).
> Scope: **identity for the public API + adversarial-input defense**.
> Out of scope: an external secret manager (deliberate; local-experimental project).

## 🪪 Identity model

- Local user table in Postgres: `(id, email, password_bcrypt, created_at, ...)`.
- `POST /v1/auth/login` → JWT (RS256), 15 min access + 30 day refresh.
- Key pair generated at first server start; stored in a Docker volume (`/var/lib/negelir/jwt/`).
- `GET /v1/me` returns the decoded claims for the authenticated user.
- No social login bundled; an OIDC plug-point exists in `server/internal/auth/oidc.go` for future use.

## 🔒 Transport security

| Channel | TLS | Auth |
|---|---|---|
| client → API gateway | yes (real cert in prod, self-signed in dev) | JWT |
| API ↔ Postgres | yes (mTLS via internal CA) | DB user/pwd |
| API ↔ Redis | yes (mTLS via internal CA) | Redis ACL |
| Agent ↔ Redis (bus) | yes (mTLS via internal CA) | Redis ACL |
| Agent ↔ Postgres | yes (mTLS via internal CA) | DB user/pwd |
| Agent ↔ Agent | **never direct** — only via bus |

The same internal CA from Phase 2 (mock stack) is reused for service-to-service
mTLS in dev. In K8s, cert-manager (or a Helm value-supplied CA) does the same job.

## 🛡️ Defense agents (Phase 7 detail)

### `sec.input.v1` — input sanitizer

Pipeline (each step bails out with a verdict):

1. **Length** > `cfg.sec_input_max_len` → `quarantine`.
2. **Charset / control chars** (zero-width, RTL override, etc.) → `sanitize`.
3. **NFC normalize** + Turkish-aware lowercase.
4. **Deterministic injection rules** (regex over known patterns: "ignore previous instructions", base64 with `eval`/`exec`, system-prompt smuggling) → `quarantine`.
5. **Small classifier** (≤ 60 MB) — only if rules were inconclusive.
6. Verdict published to `sec.alert` if not `pass`.

### `sec.scrape.v1` — upstream-data anomaly

- Monitors `scrape.raw` size, content-type, and structural fingerprint.
- In dev: compares to seed manifest (exact match expected).
- In prod: compares to a 30-day rolling fingerprint per source.
- Trips on schema drift, sudden HTML bloat, or unexpected redirects.

### `sec.rate.v1` — abuse / rate limit

- Token bucket per `client_id` (JWT) and `ip` (fallback).
- Sliding-window burst detector (`cfg.sec_burst_threshold`).
- Maintains a **denylist** in Redis hash; the API gateway consults it on every request.

## 🧨 Threat model (informal)

| Threat | Mitigation |
|---|---|
| Prompt injection in QA endpoint | `sec.input.v1`, plus templated answers (no LLM in the answer-generation hot path) |
| Source-site supply-chain attack (DOM swap, malicious JS) | `sec.scrape.v1` size/content-type check; processor parses without executing JS (no headless browser by default) |
| Credential stuffing on `/auth/login` | per-IP rate limit, bcrypt, optional account lockout (`cfg.auth_lockout_after`) |
| Bus message forgery | mTLS to Redis + Redis ACL per consumer group |
| Supply-chain in our deps | pinned digests, SBOM generated by `make sbom`, `pip-audit` + `govulncheck` in CI |
| Resource exhaustion (XXL payload to QA) | gateway max body size, agent timeouts, supervisor circuit breaker |

## �️ Right-to-erasure flow (Phase 8.3 / §8.9)

The `quarantine_samples` table holds raw flagged-input bytes that may contain PII.
The erasure flow is:

1. **Trigger.** Operator runs `ops.quarantine-erase --target <client_id>` via the ops console.
2. **Bus event.** `opsctl` publishes `maint.event.v1{kind=quarantine_erase, payload={request_id, target}}` on the bus.
3. **Handler.** `maint.backup.v1` consumes the event, calls `quarantine.erase(client_id=target)` (hard-DELETE of all matching rows), then:
   - Emits `maint.event.v1{kind=pii_erased, payload={request_id, client_id, table="quarantine_samples", row_count, erased_at}}` — the immutable audit trail.
   - Publishes `maint.ack.v1` back to `opsctl` with `accepted=true` + row count.
4. **Audit retention.** The `pii_erased` event lands in `maint_audit_log` (INSERT-only table, trigger raises `audit_log_immutable` on UPDATE/DELETE for all roles except `negelir_audit_pruner`). Retention for `pii_erased` rows defaults to `cfg.maint_audit_retention_days_overrides["pii_erased"]` = 2555 days (7 years — right-to-erasure breach evidence per GDPR Art. 17(3)).

**Edge cases:**
- If `request_id` or `target` is missing → `maint.ack.v1{accepted=false, reason="quarantine_erase missing request_id or target"}` — nothing deleted.
- If zero rows matched → `accepted=true, reason="no rows matched"` (idempotent).
- `--confirm-pii` flag required on the CLI side; omitting it exits non-zero before the bus event is published.

## 💾 PII-aware backup policy (Phase 8.3 / §8.9)

Nightly logical dumps (`maint.backup.v1`) apply a **column-exclusion list** at `pg_dump` time
to prevent raw PII bytes from entering the encrypted dump archive.

| Default excluded column | Table | Reason |
|---|---|---|
| `raw_bytes_b64` | `quarantine_samples` | Base64-encoded raw flagged input; may contain user PII |

Config key: `NEGELIR_MAINT_BACKUP_PII_EXCLUDED_COLUMNS` (default `quarantine_samples.raw_bytes_b64`).
The dump TOC's `pii_excluded_columns` list is embedded in the `backup_completed` event payload,
so operators can verify coverage without inspecting the archive.

**Sanitized projection.** The `quarantine_samples` table is still present in the dump (with the PII column excluded) so schema integrity checks and row-count verification (`verify.sql`) work normally. The companion sidecar file `negelir.quarantine_meta.csv` (shipped beside the archive) carries the non-PII metadata columns (`id`, `client_id`, `source`, `flagged_at`, `verdict`) needed for forensics without the raw payload.

**Restore invariant.** After `ops.restore`, `SELECT count(*) FROM quarantine_samples` returns 0 (the excluded column makes rows incomplete; the restore intentionally leaves the table empty). Proof test in `test_phase8_9_restore_round_trip.py`.

**Prod guard.** Setting `profile=prod` without `NEGELIR_MAINT_BACKUP_ENCRYPTION_KEY_DIR` causes the agent to refuse startup (`fail_safe_no_encryption_in_prod`). Under mock profile, a debounced daily `backup_unencrypted` warning is emitted instead.

- WAF in front of the API. Optional in cloud, not part of base topology.
- Penetration-test certification. We do internal adversarial testing in Phase 12.

## Audit-chain HMAC discipline (§8.15.7)

The opsctl audit log (`data/maint/opsctl_audit.csv`) is protected by a forward-
linked HMAC hash chain:

* **`AUDIT_HEADER`** in [`xops/opsctl/_audit.py`](../../xops/opsctl/_audit.py)
  defines the canonical column order.  It includes `prev_hmac` (HMAC of the
  preceding row's fields) and `row_hmac` (HMAC of this row's fields plus
  `prev_hmac`), anchoring each row to the one before it.
* The HMAC key is loaded from the path at `cfg.audit_chain_hmac_key_path`
  (default `/var/lib/negelir/secrets/audit_chain.key`).  The file must be
  readable by the agent and non-world-readable (mode 0600 or stricter).
* **Integrity verification** runs on agent startup and on the hourly cron.  A
  break in the chain (truncated row, injected row, or field mutation) emits
  `sec.alert.v1{kind=audit_log_integrity_break, severity=critical}` with
  `first_break_row` identifying the tampered row index.
* **Database mirror.** `maint_audit_log` and `maint_audit_log_pii` in
  [`migrations/009_maint_audit.sql`](../../migrations/009_maint_audit.sql) carry
  `prev_hmac CHAR(64) NOT NULL` and `row_hmac CHAR(64) NOT NULL` columns.  The
  `maint_audit_stamp_row_hmac` BEFORE INSERT trigger computes and validates the
  chain at insertion time.  Rows exceeding `cfg.maint_audit_row_max_bytes`
  (default 16 384 B) are truncated to a `OVERSIZE_SENTINEL` before hashing.
* **Chaos coverage:** `P12-8-AA` (`chaos-audit-truncate-attack`) in
  [`docs/testing/phase12_catalogue.md`](../testing/phase12_catalogue.md).
